# AGENTS：给 AI 编程助手的工作规则

> **硬性规则：每完成 `TASKS.md` 里的一项任务（例如 T1.2），就把这一项任务条目从 `TASKS.md` 剪切到 `doc/DONE.md`（没有就新建），并在条目后注明完成日期；`TASKS.md` 只保留未完成的任务。**

## 关于开发者
- 我是编程初学者，主要通过 vibe coding（让 AI 写代码）完成项目，HTML/CSS/JS 刚入门。
- 这是练手项目，**学会比做快更重要**。

## 每次开始新对话
1. 先读 `doc/AGENTS.md`、`doc/TASKS.md`；涉及结构或需求时再读 `doc/ARCHITECTURE.md`、`doc/REQUIREMENTS.md`。
2. 只做 `TASKS.md` 里当前这一项任务，不顺手做别的。

## 写代码的规则
- 严格遵守 `ARCHITECTURE.md` 的技术栈、目录结构和接口定义；需要改架构时先停下来说明原因，等我确认。
- 范围以 `REQUIREMENTS.md` 为准，「第一版不做」里的功能不要加。
- 代码尽量简单直白，优先少依赖；新增 npm 包前先说明用途并征得同意。
- 关键函数写中文注释，解释「为什么」而不只是「做什么」。
- API 密钥、密码只从环境变量读取，绝不写进代码或提交到 git；新增环境变量同步更新 `.env.example`。
- `widget/` 里的代码不能使用 React 或任何框架。

## 每完成一项任务
1. 自己先跑一遍验证（运行项目、调用接口或跑测试），把验证结果告诉我。
2. 用中文、面向初学者解释：改了哪些文件、每个文件的作用、这里用到的关键概念（例如 CORS、向量、余弦相似度），控制在一屏以内。
3. 告诉我怎么手动测试。
4. 我确认后，提交一次 git，提交信息用中文简述改动。
5. 把该任务从 `TASKS.md` 移到 `doc/DONE.md`，`TASKS.md` 只保留未完成事项。

## 出错时
- 先解释错误是什么意思、可能原因，再修改；不要一次改一大片来「碰运气」。
- 同一个问题修两次还没好，停下来告诉我你的判断和几个可选方案。

## 上下文管理
- 我贴报错时只会贴关键几行，需要更多信息就直接问我。
- 一项任务做完我会开新对话，所以重要的决定要写进文档，不要只留在聊天里。
