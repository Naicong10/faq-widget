# REQUIREMENTS：星河大学 FAQ 智能客服小部件

## 1. 项目目标
- 练手项目：做一个可嵌入任意网站的 FAQ 聊天小部件，只根据提供的 FAQ 资料回答访客问题，答不上来就收集访客邮箱转人工。
- 学习目标：前端嵌入脚本、Next.js 接口、关键词检索、RAG（先检索再回答）最小闭环、防止模型编造答案、数据库基础、部署上线。
- 产出：一个公开演示站 + GitHub 仓库 + 30 秒演示视频，可放进作品集和 Fiverr/Freelancer。

## 2. 演示场景
- 虚构学校「星河大学」官网（不得使用任何真实学校的名称、校徽、截图）。
- FAQ 主题：报到流程、宿舍、校园卡、选课、食堂、奖助学金、校园网、快递、校医院等，约 30–50 条，内容可参考真实情况改写。

## 3. 使用者
| 角色 | 说明 |
|---|---|
| 访客 | 在官网右下角点击聊天气泡提问的新生/家长 |
| 管理员 | 开发者本人，维护 FAQ、查看转人工留言 |

## 4. 范围
### 第一版要做（MVP）
1. **演示官网**：一个简单的「星河大学」首页，右下角嵌入聊天小部件。
2. **聊天小部件**：
   - 用一行 `<script>` 引入即可出现在任意网页右下角。
   - 点击气泡展开聊天窗口，可输入问题、显示回答，移动端可用。
   - 样式隔离，不影响宿主网站，也不被宿主网站样式影响。
3. **回答模式一：关键词版（零成本）**
   - 不调用任何模型 API。
   - 把访客问题与 FAQ 问题做相似度匹配，超过阈值返回该条答案，并附上「相关问题」建议。
   - 低于阈值时判定为「答不上来」。
4. **回答模式二：AI 版（RAG）**
   - FAQ 切片后用阿里云百炼（通义）文本向量接口生成向量。
   - 提问时检索最相关的若干条 FAQ，连同问题发给 DeepSeek 生成回答。
   - 只能依据检索到的资料回答；资料里没有就明确说不知道，并触发转人工。
   - 通过环境变量切换两种模式。
5. **转人工**
   - 答不上来时，在聊天窗口里显示表单：邮箱（必填，格式校验）+ 问题（自动带入，可修改）。
   - 提交后保存留言，并提示访客「招生办会通过邮件回复你」。
   - 不发送邮件。
6. **留言查看页**
   - `/admin` 页面，输入管理员密码后才能查看留言列表（时间、邮箱、问题、机器人原本的回答）。
   - 密码来自环境变量，不写进代码。
7. **存储**
   - 本地开发：JSON 文件。
   - 上线：Supabase 免费版数据库。
   - 通过同一个存储接口切换，业务代码不直接依赖具体存储。
8. **部署**：部署到 Vercel，演示站公开可访问。

### 第一版不做
- 注册登录、多个客户/多租户、管理后台上传 FAQ（FAQ 以文件形式放在项目里）。
- 发送邮件通知、Slack 通知。
- 收费、订阅。
- 多语言（仅中文）。
- 聊天记录长期保存（除转人工留言外）。

## 5. 非功能要求
- **不编造**：AI 版回答必须来自 FAQ；无依据时承认不知道。
- **安全**：API 密钥和管理员密码只放环境变量，不提交到 git；接口做基本的输入长度限制和简单频率限制，防止被刷额度。
- **成本**：关键词版零成本；AI 版练手阶段每月控制在几元人民币以内。
- **体积**：嵌入脚本尽量小（目标 gzip 后 < 30KB），不依赖 React。
- **可扩展**：FAQ 数据、存储、回答引擎都做成可替换模块，为以后多客户版留口子。

## 6. 验收标准
- [ ] 在任意一个空白 HTML 页面加一行 `<script>`，右下角出现可用的聊天气泡。
- [ ] 关键词版：问「宿舍几点熄灯」这类 FAQ 原题及近似问法能答对；问无关问题会转人工。
- [ ] AI 版：换一种说法提问也能答对；问 FAQ 里没有的事（例如「校长手机号」）不会编造，而是转人工。
- [ ] 转人工表单能提交，留言在 `/admin` 输入密码后可见，密码错误看不到。
- [ ] 线上版本留言存进 Supabase，重新部署后不丢失。
- [ ] 演示站部署在 Vercel，README 写清楚架构、防编造做法和本地运行方法。
- [ ] 录好 30 秒演示视频：FAQ 命中 → 换说法命中 → 未知问题转人工 → 后台看到留言。
